# 能力与差距梳理：对标主流 TODO 应用 + iOS PWA 专项

日期：2026-10-03 · 基线：`main` @ 9428f66 · 面向「慎始」自托管单用户场景

本文分两部分：

1. **功能差距** —— 按任务组织 / 提醒 / 标签 / 优先级 / 搜索 / 协作 / 跨设备同步七个维度，
   与主流待办应用横向对照，列出当前确实缺失或偏弱的能力。
2. **iOS PWA 专项** —— 针对「在 iPhone 上以主屏幕应用的方式日常使用」这一具体场景，
   逐项给出交互、启动、离线、安装、通知、状态栏与安全区的优化点与优先级。

优先级口径：

| 级别 | 含义 |
| --- | --- |
| **P0** | 不补就影响 iOS 上的日常可用性，或是与主流应用差距最致命的一项 |
| **P1** | 明显短板，一个迭代内应该补上 |
| **P2** | 锦上添花 / 长尾场景 |

## 二、功能差距（按维度）

### 2.1 任务组织

| # | 缺口 | 现状 | 建议 | 级别 |
| --- | --- | --- | --- | --- |
| O1 | 子任务只能两级 | `subtasks.parent_id` 自引用，前端只渲染两级（`types.ts` Subtask 注释） | 放开到任意层级（渲染层递归即可，DB 结构不用动），或至少三级 | P1 |
| O2 | 任务只属于一个清单 | `tasks.list_id` 单列 | 多归属（任务 ↔ 清单多对多）成本高，建议用标签/保存视图覆盖，先不做 | P2 |
| O3 | 清单内没有分区 | 排序靠 `sort_order` 与手动拖拽 | 增加「分组标题」行（section），一个清单内可分段 | P2 |
| O4 | 看板分组维度固定 | `BoardView` 按 优先级/清单/标签/时间 四种 | 允许保存自定义分组（按状态 / 按自定义字段） | P2 |
| O5 | 保存的筛选不含作用域 | `saved_filters` 只存 `TaskFilter`（优先级/标签/状态/区间/置顶/收藏），不含「作用于哪个清单 / 哪个视图 / 排序方式」；`applySavedFilter` 只改筛选 | 把 `selection`（清单/智能清单/标签）+ `view` + `sort` 一起存进筛选，成为真正的「自定义视图」 | **P1** |
| O6 | 归档是全局开关，没有「项目模板 / 清单模板」 | 有任务模板、无清单模板 | 清单模板（含子任务与相对日期） | P2 |

### 2.2 提醒

| # | 缺口 | 现状 | 建议 | 级别 |
| --- | --- | --- | --- | --- |
| R1 | 只有「相对到期的提前量」 | `tasks.reminders` 是提前分钟数组；`store/reminders.go` 按偏移扫描 | 增加**绝对时刻提醒**（如「今晚 21:30 提醒我」，与 dueTime 解耦） | **P1** |
| R2 | 页面关闭后不提醒 | 前端 30 秒轮询 `/api/reminders/due`；iOS 上 PWA 被挂起后 `setInterval` 不执行 | 见第四章「通知推送」：Apprise 为主通道，Web Push 为增强 | **P0** |
| R3 | 子任务提醒只能当天 09:00 起算 | README 已知限制 | 复用任务级提醒模型，给子任务加 `due_time` | P2 |
| R4 | 贪睡档位固定 | 有 `snooze`（5 / 30 分钟） | 支持自定义时长与「明早 9 点」这类相对表达 | P2 |
| R5 | 逾期任务没有自动顺延 | 只在「逾期」智能清单里堆积 | 设置项：`overdueAutoRoll`（逾期自动改到今天），配合晨省使用 | P2 |
| R6 | 无地理围栏提醒 | — | iOS Web 拿不到后台定位与围栏，建议**明确不做**，用「到公司 / 到家」这类手动快捷方式替代 | ✘ |

### 2.4 优先级

| # | 缺口 | 现状 | 建议 | 级别 |
| --- | --- | --- | --- | --- |
| P1 | 优先级仅是排序与颜色维度 | 4 档 + 四象限 + 可关闭（`priorityEnabled`） | 基本够用。可选增强：与到期日组合的「今日推荐序」（智能排序里把高优先级提前） | P2 |
| P2 | 无「紧急度自动衰减 / 逾期升级」 | — | 逾期 N 天后自动提升优先级或标红，成本低、体感强 | P2 |

### 2.5 搜索（差距最大的一项）

| # | 缺口 | 现状 | 建议 | 级别 |
| --- | --- | --- | --- | --- |
| S1 | 单关键词、LIKE 子串匹配 | `store/tasks.go`：`(t.title LIKE ? OR t.notes LIKE ?)`，一个 `%q%` | 空格分词后多词 AND；至少支持引号短语与 `-排除` | **P0** |
| S2 | 搜不到标签名 / 清单名 / 子任务标题 | SQL 只覆盖 title + notes | 查询扩展到 tag 名、list 名、subtask 标题、url | **P1** |
| S3 | 无结构化查询语法 | 无 | 逐步支持少量易实现的算子：`#标签` `@清单` `p:高` `due:today|week|overdue` `is:done|starred|pinned`，与自然语言解析（`lib/nlp.ts`）共用词法 | **P1** |
| S4 | 无搜索历史 / 无常用搜索保存 | 无（保存的筛选是另一套） | 最近搜索 10 条（本地存），一键保存为筛选 | P2 |
| S5 | 结果无高亮、无排序 | — | 命中片段高亮 + 按相关度/更新时间排序 | P2 |
| S6 | 中文依赖 LIKE，无法做拼音/首字母 | — | 可选：写入时维护 `search_blob`（标题+备注+标签拼音），成本换体验 | P2 |

### 2.6 协作

| # | 缺口 | 现状 | 建议 | 级别 |
| --- | --- | --- | --- | --- |
| C1 | 无多用户、无分配人、无评论 | 单用户，`SHENSHI_TOKEN` 是全局门禁 | 与「自托管单用户」定位一致，**不建议做完整协作** | ✘ |
| C2 | 无法把单个清单分享给家人（只读） | 无 | 最小可行：为某个清单生成只读链接（`?token=` 只读副本 + 独立口令），不做写协作 | P2 |
| C3 | 活动流不区分来源 | `activities` 记 kind/title，无 actor | 引入「来源标签」（web / caldav / 导入 / webhook），排查「谁改了我的任务」很有用 | P1 |
| C4 | 无 @提及、无评论线程 | — | 不做；任务备注 + 关联任务已能承载 | ✘ |

### 2.7 跨设备同步

| # | 缺口 | 现状 | 建议 | 级别 |
| --- | --- | --- | --- | --- |
| Y1 | 没有实时通道 | 写操作后本端 220ms 去抖对账；`bootstrap` 5 分钟轮询；提醒 30 秒轮询；无 SSE / WebSocket | 加一条 SSE（`GET /api/stream`）广播 `version`，其他设备收到即 `reconcile()`。Go 标准库即可实现，无需新依赖 | **P1** |
| Y2 | 无增量同步 | 每次整表拉 | 给 tasks 加 `updated_at` 游标接口（前端无 cache 层，收益有限） | P2 |
| Y3 | 并发修改后写覆盖 | PATCH 无条件写入，无 `If-Match` | 支持 `If-Match: <updatedAt>`，不匹配返回 409，前端提示「这条在别的设备上被改过」 | **P1** |
| Y4 | 离线队列只在本机 | outbox 在 IndexedDB（`lib/offline.ts`），换设备不可见；iOS 长期不用会清站点数据 | 队列条数在 UI 常驻显示 + 「立即重试」；服务端提供「最后写入时间」供人对账 | **P1** |
| Y5 | 换设备 / 重装后离线数据丢失 | 同上 | 明确边界即可，不做端对端同步 | ✘ |
| Y6 | 无第三方格式导入 | 导入只认自家备份 JSON/ZIP | 支持 Todoist CSV / 标准 iCalendar(.ics) 导入 —— 迁移成本是别人用起来的第一道门槛 | **P1** |

## 三、iOS PWA 专项

> 前提：iOS 上 PWA 的能力边界由系统决定 —— 没有 Background Sync、没有 Badging API、
> 不支持 Web Share Target、不支持 manifest `shortcuts`；Web Push 自 iOS 16.4 起可用但
> **必须先添加到主屏幕**。以下建议都在这个边界内。

### 3.1 交互体验

| # | 现状 | 优化点 | 级别 |
| --- | --- | --- | --- |
| I1 | 全局只处理 keydown，没有 touch 手势 | **任务行滑动操作**：右滑完成、左滑更多（改期/删除）。standalone 模式下没有系统返回手势，边缘滑动不会冲突 | **P0** |
| I2 | 右键菜单（`contextmenu`）在 iOS 上长按不触发 | 为任务行加**长按菜单**（复用同一套菜单项），并抑制 `-webkit-touch-callout` | **P1** |
| I3 | 未处理 `visualViewport` | 键盘弹出时底部快速添加栏 / 明细浮层会被遮住。监听 `visualViewport.resize`，把操作条抬到键盘之上；`window.scrollTo` 保证输入框可见 | **P0** |
| I4 | 输入框字号需复核（`Toolbar` 多处 `text-[0.8125rem]` 量级） | iOS 上 `font-size < 16px` 的输入框聚焦时会**自动放大页面**，破坏布局。所有输入框 ≥16px（可用 `transform` 或设计上接受更大字号） | **P1** |
| I5 | 布局偏紧凑（用户明确偏好紧凑） | 触控目标（勾选框、删除、更多）**视觉可小、热区 ≥44×44**（padding 撑开），行高本身不变 | **P1** |
| I6 | standalone 下没有刷新按钮和地址栏 | 提供**下拉刷新**（列表顶部）或设置里的「重新加载数据」，否则用户只能杀进程 | **P1** |
| I7 | 抽屉 / 详情 / 搜索多层浮层靠 `Esc` 退出 | 手机上没有 Esc：每层都要有**明确的关闭按钮**，且逐层返回（详情 → 列表 → 抽屉）路径完整 | **P1** |
| I8 | 无触觉反馈 | iOS 不支持 `navigator.vibrate`，改用**视觉反馈**（勾选的墨迹动画、Toast）即可，不要留空 | P2 |
| I9 | 无出站分享 | 任务详情加「分享」走 `navigator.share`（标题 + 深链），便于发到微信/备忘录 | P2 |

### 3.2 启动性能

| # | 现状 | 优化点 | 级别 |
| --- | --- | --- | --- |
| B1 | SW 对导航与 `/api/*` 一律**网络优先**（`sw.js` 的 `networkFirst`） | 弱网（地铁/电梯）冷启动会一直等网络，白屏。改成 **stale-while-revalidate**：先用缓存渲染，后台刷新后增量更新；或给 `fetch` 加 1.2s 超时兜底回缓存 | **P0** |
| B2 | 首屏 `bootstrap` → `tasks` 串行 | 允许并行；并缓存 `bootstrap` 做「秒开 + 后台校正」 | **P1** |
| B3 | 单包 545KB JS（gzip 约 160KB） | 日历 / 统计 / 看板 / 习惯 按视图 `React.lazy` 拆包，首屏只加载列表视图 | **P1** |
| B4 | 启动画面闪白 | `manifest.background_color` 与 `theme-color` 都是浅纸色，深色主题下启动/状态栏是白条。加 `prefers-color-scheme` 两份 `theme-color` meta 并随设置更新；`background_color` 取一个深浅都过得去的中性色 | **P1** |
| B5 | 字体已本地化并进 SW 预缓存（好） | 加 `<link rel="preload">` + `font-display: swap`，避免首屏 FOIT | P2 |
| B6 | 冷启动是品牌 loading 页 | 可接受；进一步可在 `index.html` 内联一份极简骨架，减少白屏时间 | P2 |

### 3.3 离线可用

| # | 现状 | 优化点 | 级别 |
| --- | --- | --- | --- |
| F1 | outbox 覆盖：查看 / 新建 / 编辑 / 完成 / 改期 / 删除；**不含**附件、批量、子任务、习惯打卡、复盘 | 优先把**习惯打卡**与**子任务勾选**纳入队列（移动端高频，且最容易在没信号时想用） | **P1** |
| F2 | 附件完全离线不可用 | 附件写操作可先存 IndexedDB Blob，联网后补传（附件接口是 multipart，重放要支持 Blob） | P2 |
| F3 | 队列状态可见性弱 | 顶部常驻「N 条待同步」+ 手动「立即重试」；长时间未同步给出提示 | **P1** |
| F4 | iOS 会清理 7 天未打开的站点数据 | 无法绕开。缓解：队列条数在服务端可核对（每条带幂等 key），并在登录后提示「上次离线队列已丢失」 | P2 |
| F5 | 多标签同时重放可能重复新建（README 已述） | 新建请求带客户端生成的 `client_id`，服务端做幂等去重 | **P1** |

### 3.4 添加到主屏幕

| # | 现状 | 优化点 | 级别 |
| --- | --- | --- | --- |
| A1 | 完全没有安装引导（代码里无 `beforeinstallprompt` / 安装卡片） | iOS 无法用 JS 触发安装。做**首次访问引导卡片**：检测 `navigator.standalone` 与 `display-mode: standalone`，未安装时图示「分享 → 添加到主屏幕」，可关闭且只提示一次 | **P0** |
| A2 | 装到主屏后需要重新输口令（PWA 与 Safari 存储隔离） | Cookie **已有 `MaxAge: 30 天`**（`auth.go` setAuthCookie），不是会话 Cookie，这条原判断有误。剩下要做的只是引导：安装引导里提供「带口令的深链」（`?token=` 已支持），并说明装到主屏后需登录一次 | **P1** |
| A3 | manifest 无 `screenshots` | 补 1~2 张（桌面安装 UI 用，iOS 不读，成本极低） | P2 |
| A4 | `start_url` 是 `/` | 可加 `?src=pwa` 便于区分来源；`scope`/`id` 已正确 | P2 |
| A5 | 更新提示卡片已有（好） | iOS 上新版有时要**彻底关掉应用再打开**才生效，卡片文案需说明这一步 | **P1** |
| A6 | 无「已安装」状态区分 | 已装时隐藏安装引导，并可在设置里显示「离线能力已启用 / 未安装」 | P1 |

### 3.5 通知推送

| # | 现状 | 优化点 | 级别 |
| --- | --- | --- | --- |
| N1 | 页面内 30 秒轮询 + WebAudio 提示音；iOS 上 PWA 挂起后定时器不跑 | **Apprise 服务端推送（`internal/push`）是当前唯一能在页面关闭时到达的通道**，把它扶正为 iOS 主通道：首次配置引导（ntfy / Bark / 企业微信 / 邮件等）、「提醒 + 每日概览 + 逾期汇总」三类消息、设置页自检按钮 | **P0** |

## 五、验证方式

改动落地的检查顺序沿用项目既有纪律：

```bash
cd web && pnpm typecheck            # 类型
cd server && go vet ./...           # 静态检查
python3 scripts/smoke.py            # 后端端到端
node scripts/ui-smoke.mjs           # 浏览器 UI 冒烟
node scripts/pwa-smoke.mjs          # PWA / 离线冒烟
```

iOS 专项的适配类改动（V1 / V2 / V3 / I3）无法在桌面 Chromium 上验证，
建议在 `scripts/` 下加一份**真机检查页**（`/dev/ios-check`）：
在页面上直接打印 `navigator.standalone`、`display-mode`、`innerHeight`、
`visualViewport.height`、`env(safe-area-inset-*)` 的计算值、键盘弹出前后的差值，
手机 Safari 打开即可逐项核对。
