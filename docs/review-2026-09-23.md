# 「慎始」产品审查报告（2026-09-23）

> 审查范围：整体业务逻辑、各菜单功能的实现与交互、新增数据的添加流程。
> 结论分三类：**需要优化的环节** / **建议新增的功能** / **应当修改调整的部分**，每条注明问题、影响与优先级。

**总体评估**：产品主线「规划 → 执行 → 复盘」闭环完整，理念功能（晨省/日省/专注/今日三件事）均已落地，数据骨架（`AppStore` 单源 + 220ms 去抖对账）自洽。但存在 **6 个 P1 级业务/安全缺陷**、**三套统计口径不一致**、**多处交互死路**，且全仓库零单元测试、两项已知失败用例（模板 94/96）已定位到根因。

优先级口径：**P1** = 核心业务错误 / 安全漏洞，立即修；**P2** = 中，影响体验或一致性，应排期；**P3** = 低，边角打磨。

## 三、应当修改调整的部分（做错了/不一致，必须改）

### P1 — 核心业务正确性 / 安全

| # | 问题（文件:行号） | 影响 | 修复方案 |
|---|---|---|---|
| 1 | **重复任务静默断链**：完成有两条路径——`/toggle` 会续期，但详情面板走 `PATCH {status:'done'}`（`TaskDetail.tsx:317`），而 `UpdateTask` 的 status 分支无续期逻辑（`tasks.go:764-776`） | 用户以为本次完成已排好下次，实际规则从此中断、任务不再出现 | 方案 A：`UpdateTask` 的 status→done 分支复用 toggleTask 续期逻辑（同事务）；方案 B：前端统一改走 `/toggle`。建议 A+B 都做（API 层兜底） |
| 2 | **子任务提醒永远无法 ack**：hit 的 `task.id=0`（`reminders.go:135-141`）→ 前端 ack 传 0 → handler 拒 `TaskID<=0`（`handlers_meta.go:383`）→ 台账不落账；即便改传负数 `-subtaskID` 也会被拦 | 72h 窗口内子任务提醒每次刷新全部重弹，无法消除 | `ReminderHit` 携带稳定可 ack 的 id（沿用台账约定 `-subtaskID`）；handler 改为拒绝 `taskId==0`；前端改传该字段，去重 key 同步 |
| 3 | **导入路径穿越（读/写/删三向）**：replace 模式 `stored=a.File` 原样写盘（`backup.go:343-351`）、`insertAttachments` 只清洗 `name` 不清洗 `file`、undo 删除同 join | 登录后导入恶意备份可读写删服务器任意文件 | 导入时强制 `file = filepath.Base(file)`，拒绝 `..`、绝对路径、分隔符；`AttachmentPath`/`writeAttachmentFile` 入口兜底校验 |
| 4 | **`DELETE /api/lists/{id}` 三连缺陷**（`org.go:380-390`）：①不进 undo（清单内任务**永久删除不可撤销**）②不 emit（CalDAV/Webhook 无记录）③不清理磁盘附件（FK CASCADE 后成孤儿） | 对照单任务删除有完整 undo，清单删除是野蛮路径 | 删除前查出任务，批量 `stageUndo` + 逐条 `deleteTaskRows`（复用任务删除路径） |
| 5 | **CalDAV 增量同步截断丢变更**：先取全局 `maxSeq`（`extras.go:730`）再 LIMIT 500，却把全局 maxSeq 写进 sync-token（`sync.go:240`） | 批量导入后手机日历与服务端永久脱节 | 截断时返回**最后一条已返回变更的 seq**（而非全局 maxSeq），或取消截断按批多轮回 |
| 6 | **清空日期留僵尸日程**：`if t.DueDate != nil \|\| deleted` 跳过 events 删除（`backend.go:233`），与 232 行注释自相矛盾 | 手机日历上去掉日期的旧日程永远不消失 | dueDate 由有→无时补记 `deleted=true`（调用方携带变更前值或对比逻辑） |

## 落地路线

1. **第一批（阻断性）**：P1 六项 + 侧栏点击不高亮 + 多选 Esc 死路 + 习惯归档恢复 —— 用户可直接撞上的墙。
2. **第二批（一致性）**：统一 open 口径（`status IN ('todo','in_progress')`）、统一提醒状态/归档过滤、统一日期校验、补事务与 emit、修 `replaceSubtasks`。
3. **第三批（防回归）**：`repeat.go` 等纯函数补单测、`check-nlp` 进 CI、修 README 测试路径、先关提醒浮层再测模板（94/96 即可变绿）。
