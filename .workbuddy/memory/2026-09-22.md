# 2026-09-22 · 慎始 v1 交付

## 目标
用 Go + React 复刻滴答清单核心功能，交付名为「慎始」的可用任务管理应用（出处《礼记》「慎始而敬终」）。

## 交付物
- `server/`：Go 标准库 HTTP + modernc.org/sqlite（纯 Go，无 cgo，WAL）。`go:embed all:dist` 把前端打进二进制。
- `web/`：React 19 + Vite 8 + TS + Tailwind v4，自建状态层（Context），无第三方 UI/图标库。
- `bin/shenshi`：11MB 单文件，运行只需它 + 一个 .db。
- `scripts/build.sh`（前端→server/dist→go build）、`scripts/smoke.py`（后端 73 项）、`scripts/ui-smoke.mjs`（真实 Chromium 26 项）。
- `README.md`、`docs/screenshots/`。

## 验证结果
- `go vet ./...` 通过；`tsc --noEmit` 通过；后端冒烟 73/73；UI 冒烟 26/26（含「无控制台错误/无未捕获异常」硬性检查）。

## 关键设计决策
1. **筛选口径在后端**：智能清单（today/next7/overdue…）用 SQL 条件驱动，不把全量数据拉到前端过滤。
2. **三态字段 `Opt[T]`**：区分「未传」与「显式置空」，PATCH 语义清晰（`dueDate: null` = 清空日期）。
3. **清单列表与角标口径分离**：`whereCount()` 只统计未完成（角标），`where()` 保留「今日已完成」并沉底到「已完成」分区。这是本轮修掉的真实缺陷——原先勾掉的任务会从「今天」凭空消失，而列表里预留的 `done` 分区永远为空。**结论：列表查询与计数查询不能共用一个 where()。**
4. **重复规则**自建紧凑语法（`weekly:1,3,5` / `monthly:last` / `ebbinghaus:0`），后端 `NextOccurrence()` 统一解释。
5. **搜索态还原**：`setKeyword('')` 必须回到进入搜索前的选择，否则清空搜索框会滞留在 `{kind:'search'}`，导致四象限等视图只剩搜索结果（本轮修复，用 `preSearch` ref 记录）。
6. **种子数据不预置提醒偏移**：原先 seed 的 `reminders='[0]'` + 过去时间会让首次打开就弹两条逾期提醒，改为 `'[]'`。

## 环境经验（沙箱/本机）
- `go` 不在默认 PATH，在 `/opt/homebrew/bin/go`；脚本里统一做「PATH → /opt/homebrew → /usr/local/go」兜底，`GO_BIN` 可覆盖。Python 脚本内也要用 shutil.which 兜底，不能只依赖 `GO_BIN`。
- 本机 curl 访问 127.0.0.1 会被代理拦截（502 upstream connect failed），必须加 `--noproxy '*'`。
- zsh 下 `rm -f /tmp/x*` 无匹配会直接报错并中断 `&&` 链，需改用显式文件名。
- 后台服务在 Bash 工具调用结束后会被回收，探测要在同一次调用内完成。
- 本机已有 Playwright Chromium 缓存（`~/Library/Caches/ms-playwright/chromium-1234/chrome-mac-arm64/Google Chrome for Testing.app/...`），装 `playwright-core` 即可复用，无需下载 500MB。

# 2026-09-22 · 第二轮迭代（批次一：1-5 + 部署前置）

## 背景补充

## 本轮完成（#10-#13）
1. **手动拖拽排序**：`sort_order` REAL 列启用。`orderByFor(sortBy)` 取代固定 `taskOrderBy`，排序模式 `smart/manual/priority/due/created/title`。
2. **导出/导入**：`server/internal/store/backup.go`（新）。JSON 全量 + CSV 任务表；导入 `merge`（追加）/`replace`（清空重建）。
3. **重复任务「跳过本次」**：`SkipTask()` 只把 `due_date` 推到下一次，不写 `completed_at`、不生成新副本——与「勾选完成」语义严格区分。
4. **日历日视图 + 时间轴**：`DayView` 组件。24 小时纵轴（HOUR_H=52px），任务按 `due_time`/`end_time` 成块排布，重叠任务按「簇」分道并排；点空白处 15 分钟吸附就地点建；拖动改时刻；拖回顶部「全天」区撤销时刻（`dueTime: null`）。

## 本轮踩到的坑（重要）
- **`sort_order` 回绕**：`CreateTask` 原先用 `time.Now().UnixMilli()%1_000_000`，约 16.7 分钟后回绕，新任务会跑到列表顶端。改为读 `MAX(sort_order)+1024`。
- **手动排序「看起来没生效」**：`sort_order` 原本排在 ORDER BY 第 5 位（due+priority 之后），永远轮不到它起作用。必须按模式重构 ORDER BY。
- **Popover 点击被吞（真实 bug）**：`header` 上的 `backdrop-blur` 会创建层叠上下文，使其落在内容区之下，透明的 QuickAdd 容器因此拦走点击。修法：header `relative z-30`、aside `relative z-20`。
- **`txer` 接口签名必须与 `database/sql` 完全一致**：`Exec/Query/QueryRow` 的返回值要写 `sql.Result`/`*sql.Rows`/`*sql.Row`，手写 `interface{ LastInsertId() }` 之类会让 `*sql.Tx` 无法满足接口。
- **CSV 断言别按 `\n` 切分**：备注字段自带换行，要用 `csv.reader`。
- **Playwright 的 `getByRole(name)` 对「中文+ASCII 混排」可访问名不可靠**，改用 `locator('button', { hasText })`；更稳的做法是给控件加 `data-*` 钩子（本轮给日历加了 `data-cal-mode`/`data-day-axis`/`data-day-block`/`data-day-allday`/`data-day-add`）。

# 2026-09-22 · 第三轮（批次一收尾：#13 日视图 + #14 习惯）

## #13 日历日视图（`CalendarView.tsx` 的 `DayView`）
- 24 小时纵轴，`HOUR_H = 52`，`PX_PER_MIN = HOUR_H/60`。`yOf(min) = min * PX_PER_MIN`。
- 任务块用 `due_time` 定位、`end_time - due_time` 定高（缺 `end_time` 默认 45 分，块高下限 26px）。
- **重叠任务按「簇」分道并排**（`placeDay()`）：按开始时间排序，贪心取第一个未被占用的 lane，簇内统一按簇的 lane 数等分宽度。
- 点空白处 15 分钟吸附就地点建；拖动块改时刻；拖回顶部「全天」区 = `dueTime: null`。
- 每天首次进入滚动定位到当前时刻（用 ref 读 nowMin，避免分钟刷新时反复滚动）。

## #14 习惯打卡
- 新表 `habits` / `habit_logs`（`(habit_id, day)` 唯一），`habits.go` + `handlers_habits.go` + `HabitsView.tsx`。
- 节奏两种：`daily` / `weekly`（`weekdays` 逗号分隔，0=周日，与 Go `time.Weekday()` 同口径）。
- **`target` = 当天达标所需次数**：一天判定为「达标」= 当天 count 之和 ≥ target。
- **`start_date` 语义**：之前的日期不算排期日 → 不计入 `due`（应做次数）与达标率分母；
  **但如果那天确实补记了打卡，则计入连续天数**（否则新建习惯后补记前几天会白记）。
- **连续天数**：从今天往回数；今天未达标不算断档，从昨天起算（今天还没过完）。
- **`due` 右界取今天**：`to` 若超过今天，未来的排期日不算欠账。
- 热力图：周为列、星期为行，`gridTemplateRows: repeat(7, 13px)` + `gridAutoFlow: column` +
  cells 按「周优先」排列，三者缺一不可（最初写成 flex 单行 84 格，直接横向溢出 1520px）。
- 打卡 API：`POST /api/habits/{id}/check`（不传 `count` 为加一次，传 0 即删记录）/ `DELETE ...check?day=`。
- 已并入导出/导入：`habits` / `habitLogs`；merge 时流水重挂到新习惯 id，同日冲突取 `MAX(count)`。

## 新增的坑
- **允许空请求体的接口要用 `decodeOptional`**：`decode` 遇到空 body 会报 `请求体解析失败: EOF`，
  而打卡这类「不传即取默认」的接口必须容忍空 body（这个坑让一批断言连带失败，排查时容易被误导）。
- **DELETE 统一返回 200 + body**（`{"ok":true,"id":...}`），不要用 204，否则与既有接口口径不一致。
- Go 的 `time.Weekday()` 是 0=周日，Python 的 `date.weekday()` 是 0=周一，写跨语言断言要换算：`go_wd = (py_wd + 1) % 7`。
- smoke.py 里的 `today` 是 `date` 对象，用它拼 JSON 会 `TypeError`，要 `today.isoformat()`。
- 后台服务在单次 Bash 调用结束后被回收，**启动 + curl 验证必须在同一次调用内完成**。

# 2026-09-22 · 第四轮（批次二：#15 Docker + 访问口令鉴权）

## 背景
用户确认服务要上服务器 Docker、多端网页访问 → 公开部署必须先把裸奔的 `/api` 关起来。
实现为**可选口令**：`SHENSHI_TOKEN` 为空 = 现状（本地/内网自用，零摩擦）；非空 = 全站门禁。

## 后端
- `api/auth.go`（新）：`gate` 中间件包住整个 `http.ServeMux`（`api.go` 里 `s.root = s.gate.wrap(s.mux)`）。
  - 白名单：`/api/health`、`/api/auth/*`（否则登录页自己都打不开）。
  - 口令比对用 `subtle.ConstantTimeCompare`，不走 `==`（防时序侧信道）。
  - 凭据三通道：Cookie → `Authorization: Bearer` → `?token=`。Cookie 为 HttpOnly + SameSite=Lax，HTTPS（`X-Forwarded-Proto`）下加 Secure。
  - **非 API 请求的 401 直接吐内联登录页**（`writeLoginPage`，自包含 HTML、noindex）——这样前端没构建、只有二进制的场景也能登录。
  - 失败节流：同一 IP 5 分钟内错 8 次 → 429（IP 从 `X-Forwarded-For` 取，反代后仍准）。
- `api/handlers_auth.go`（新）：`/api/auth/status`（required/authenticated）、`login`、`logout`。
- `main.go` 加 `-token`（默认取 `$SHENSHI_TOKEN`），为空时启动打印告警。

## 前端
- `client.ts`：加 `setUnauthorizedHandler`，任何响应 401 → 交给上层（不只是 API 调用点）。
- `AppStore`：`locked` / `unlock`；`App.tsx` 渲染 `LockScreen`（输入口令 → login → `location.reload()`，不自己拼状态，省掉一整类「解锁后数据不一致」的坑）。

## Docker
- `Dockerfile` 三段式：node:22-alpine 构建 web → golang:1.27-alpine `CGO_ENABLED=0 GOOS=linux` 静态编译（`-trimpath -ldflags="-s -w"`）→ alpine:3.20 只带 tzdata + ca-certificates，非 root 用户跑。
- `TZ=Asia/Shanghai` 必须设：`model.Now()` 与「今天是哪天」的判定全依赖本地时区，容器默认 UTC 会让日视图/打卡跨日错位。
- `VOLUME /data`，`SHENSHI_DB=/data/shenshi.db`；compose 用命名卷 `shenshi-data`，`SHENSHI_TOKEN` 写 `${SHENSHI_TOKEN:?...}` 强制来自 `.env`，绝不硬编码进 compose。

## 新增的坑
- **本机没装 docker**，`docker build` 无法验证 → 转而验证风险最高的假设：
  `CGO_ENABLED=0 GOOS=linux GOARCH=amd64/arm64 go build` 能出 11MB 静态 ELF（`file` 确认 not a dynamic executable）。这是 Docker 构建里唯一可能翻车的环节（其他都是 COPY/ENV）。
- UI 冒烟里「解锁过程无控制台错误」一开始失败：401 探测本身会在控制台留下 `Failed to load resource: 401`。
  这是**预期噪声**，用 `EXPECTED_AUTH_NOISE` 只在鉴权小节过滤；主体「无控制台错误」检查保持严格。

1. **版本声明**：新增 `.nvmrc`（`24`）、`web/package.json` 加 `engines.node = ">=24"`（已写进 lockfile）。
2. **Dockerfile**：`node:22-alpine` → `node:24-alpine`；`alpine:3.20` → `alpine:3.24`（3.20 已落后 3 个大版本）。

4. **后端依赖**：`go get -u ./...` + `go mod tidy` →
